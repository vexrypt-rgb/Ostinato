# Legato readiness

Legato is the planned any-angle navigation layer: it steers along straight lines between visible points instead of
following the block-grid path move by move. This note lists the contracts it has to respect, where it should plug in,
and the limits the current architecture puts on it. It was written at the end of Presto v4.1 and is not an
implementation; nothing here is wired.

## Movement contracts

Each contract is enforced somewhere today. Legato must keep it or replace it with an equivalent that is tested.

| Contract | Where it lives now | What Legato must do |
|---|---|---|
| **Rotation slew limit** | `LookBehavior.calculateMouseMove`: at most 32° of yaw per tick (`ostinato.aim.deg`; Grace Note raises it to 90 for one tick with `turnCap`). Rotations go out as mouse steps, quantised by sensitivity. | Plan every turn at no more than 32°/tick. A heading change of θ costs ⌈θ/32⌉ ticks in which the move direction is not the planned one. Sharp any-angle corners are not free. |
| **Camera-relative input** | Keys are W/A/S/D relative to the look, not world directions. `PhysicsTravel.offPlan` declines to press forward when the look is more than 45° off the plan. `KinematicController.turningAround` declines past 90°. `MovementChainJump.turnFirst` stands still until the look is within 45°, and since v4.1 so does SimTravel before a fresh plan. | Never press movement keys while the look is outside the gate. A key pressed mid-turn moves the player along the *current* look: presto-v4-fix6 lap 4 jumped backwards into a gap (`ChainJumpTurnFirstTest`). In v4.1 run 3 it caused three side falls at handovers to SimTravel, including the long-unexplained x≈21.6 one (`SimTravelTurnFirstTest`). Every driver needs this gate, because the previous driver may have left the look anywhere. |
| **Run-up** | `MovementJump`/`JumpTemplates` carry the run-up length (`t.runUp`). The kinematic rollouts start from the measured velocity. `walkToSpot` backs up to the run-up start. | A jump on an any-angle line needs the same run-up along that line. If the line starts too close to the edge, back up first; don't shorten the jump. |
| **Jump/landing feasibility** | `KinematicController.drive` rolls out candidate delays and yaw offsets in `PlayerSim`. A long jump must pass `holdsWithMargin`: take-off 0.25 back along the velocity and ±0.15 to the side (`marginShifts`). Since v4 fix 6 this includes the short-aim candidate (`ShortAimMarginTest`). | Run every jump through the same rollout and the same margin shifts. Any-angle take-offs are off-centre by nature, and the lateral shifts are what catch "lands with no slack". |
| **Ground support** | Rollouts collide against `ClientWorld`/`BsiWorld`. A plan that leaves the walkway is scored down; "nothing makes progress safely" returns -1. | Check that a straight line across a block corner stays on support for the player's full 0.6-wide box, not just its centre. A cut corner is a side fall: on a one-wide walkway 0.2 of sideways error is enough (the handoff's side falls at x≈7.2, 21.6 and 33). |
| **Movement ownership** | One input writer: `InputOverrideHandler`. `PathExecutor.tickOnce` gives the tick to the first driver that returns ≥0 (EXTEND → KINEMATIC → kinematic family → PHYSICS → SIM → Baritone). A driver holding a position longer than `DRIVER_PATIENCE` (100 ticks) is handed back with fault M01 and rests 60 ticks. | Be one more driver in that chain, returning -1 to decline. Don't write keys from anywhere else. |
| **Releasing input on handover** | `SimTravel.tick` lets go of keys on the first tick it no longer presses (`SimTravel.releases`). `PathExecutor` clears keys on the M01 hand-back. | Release held keys the tick you stop driving, including on a successful advance. Held sprint after a handover walked the player off the walkway (`SimTravelAtGoalTest`). |
| **Open-loop plans expire** | `SimTravel.stale`: a stored plan resumes only on the tick right after its last pressed step and only for the movement destination it was solved for; otherwise it is solved again from the current state. `drift()` (0.45 from the predicted position) covers the steps after the first. | Treat any precomputed key sequence or line as valid only while you drove every tick since computing it. If another driver, Grace Note, or a correction had a tick, re-plan. |
| **Path advancement** | Drivers return the new `pathPosition`. Physics/sim sync it by matching the feet to path nodes (`syncPosition`). Kinematic advances along its line, built over up to `MAX_LOOKAHEAD_MOVES` drivable moves. | The path is still a list of grid nodes, so map progress along the any-angle line back to a node index. It must never jump past a move Legato can't execute (break/place/ladder/water), and must not rewind without cause; the harness counts rewinds. |
| **Cancellation** | `softCancelIfSafe` and `secretInternalSegmentCancel` drop the path and call `invalidatePresto`. A pause is taken only when `isSafeToCancel` says it's safe. | Report "not safe to cancel" while airborne on a planned jump, and drop every plan on cancel. |
| **Grace Note preemption** | `PathingBehavior.requestEmergencyHold` (asked every tick it's wanted) holds the executor before it ticks. Grace Note's `HoldProcess` pauses every other process. It also owns the look (`turnCap(90)`). | Expect to be skipped without notice. Hold no state that assumes it drove last tick, and resume by re-planning from where the player actually is. |
| **Scherzo / combat ownership** | When `PvpProcess` is active, Presto is ineligible (`KinematicController.audit`). Combat movement (`CombatMovement`) writes its own keys and asks the controller only `jumpHelps`. Scherzo is advisory for aim. | Stand down while PvP is active. Don't steer the look during a fight. |
| **Presto integration** | Presto only *removes* options: it vetoes or defers a jump, declines a long-jump stretch, or holds a hop. Ownership is checked every tick in `audit`. Predictions run with a 5 ms deadline (SCREENING) over a 40-tick horizon. Pending audits are invalidated on correction, world event, emergency hold, cancel, or setting off. | Ask Presto about jump take-offs through the same `takeoffCheck` seam. Don't give it new powers, and don't rely on it to rescue a plan that fails the margin check. |
| **World / dimension change** | `TickEvent.Type.OUT` (no world) clears the Presto correction flag, invalidates Presto, drops the emergency hold and cancels everything. `onWorldEvent` invalidates Presto. A server position packet (`ClientboundPlayerPositionPacket`) marks a correction. | Drop the plan on a world change and on any server correction, then re-plan from the corrected position. |

## Best integration points

1. **The kinematic controller's line, not a new driver.** `KinematicController.buildLine` turns the next drivable moves into a polyline, and `aim()` steers at a point 1.6 ahead on it (0.4 for the short aim). An any-angle line slots in here as a different polyline. That reuses the rollouts, the margin check, Presto's take-off seam, the turn gates and the existing advancement. This is the smallest change and inherits every contract above.
2. **A `TravelStack` layer** (`TravelStack.Layer`) between KINEMATIC and PHYSICS, only if Legato needs to drive moves the kinematic controller refuses (`drivable()`). It would need its own advancement and release logic and its own tests for the table above.
3. **Path smoothing before execution**, by marking which consecutive grid moves a straight line can replace. The executor would still own advancement node by node.

## Architecture limitations

- **The path is grid nodes.** `IPath.positions()` and `pathPosition` are block indices, and an any-angle segment spans several of them. Advancement has to be inferred from where the feet are (as `syncPosition` does), and a wrong inference rewinds or skips.
- **Moves that change the world** (break/place/pillar/ladder/water) stay with Baritone movements and the kinematic family. A straight line cannot cross them.
- **One driver per tick, first one wins.** There is no blending, and a driver that declines mid-manoeuvre hands the next one a player in motion. Several traced falls happened at a handover: the v4 4-gap falls (Baritone's parkour flying a jump the kinematic controller declined), the v4 fix2/fix3 landing overruns on 40–44, and in v4.1 the 40–44 walk-offs from a stale SimTravel plan (below).
- **A driver that is skipped keeps its state.** Lower drivers only tick when the ones above them decline, so any plan they hold can outlive many ticks of someone else's driving. v4.1 run 2 laps 1, 13, 18: SimTravel stored a one-step-pressed plan at the step up (x 20.7) and replayed it twenty blocks later at Jump 40>44. Fixed by `SimTravel.stale` (`SimTravelStalePlanTest`), but the pattern applies to any new driver.
- **The look rate is a hard limit.** Any-angle paths with many small heading changes cost turn ticks. The 45° and 90° gates make a sharp corner a stop-and-turn.
- **The rollout sim is the controller's.** `PlayerSim` matches vanilla on this course. Effects, other attributes, ice and slime, and other entities are not modelled for every case (see `Presto.supportsBody`).
- **The live harness covers one straight course** along +x with |z| ≤ 1. There is no course for diagonal lines yet, so Legato needs its own harness geometry (cf. `PrestoCourse`) before any A/B.
